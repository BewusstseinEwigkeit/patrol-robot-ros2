## 1. 验证环境

| 项 | 值 |
|---|---|
| 验证机器 | Windows 11（build 26200，AMD64） |
| ROS 2 | **Humble**（RoboStack 发行版，`ros-humble-ros-base` + turtlesim/tf2/rosbag2） |
| Python | 3.14.8（conda-forge 构建） |
| 验证时间 | 2026-10-18 |
| 环境位置 | `C:\ros2\envs\humble`（micromamba 管理） |

**为什么在 Windows 上验证**：目标机器是双系统，验证时人在 Windows 侧，
无法重启进 Ubuntu。RoboStack 提供的是**真正的 ROS 2 Humble**（不是模拟），
所以 rclpy 的 API、话题行为、tf2 语义、rosbag2 格式都与 Ubuntu 版一致。

**与目标环境的已知差异**（影响很小，但要说清楚）：

| 差异点 | 影响 |
|---|---|
| Python 3.14 vs Ubuntu 22.04 的 3.10 | 本工作区代码只用 3.10 就有的语法（`from __future__ import annotations` + `X \| None`），两边都能跑；已在本机用系统 Python 3.13 和 ROS 的 3.14 各跑一遍 |
| RoboStack 的 Windows 构建 vs apt 的 Ubuntu 构建 | `colcon build` 在 Windows 侧不可用（见 3.1），但代码与构建配置本身是标准的 ament_python 写法 |
| 没有 rviz2 | 本工作区不依赖 rviz2，验收全部走话题/tf/rosbag |

## 3. 未验证项（明确列出）

### 3.1 `colcon build` 在 Windows 侧不可用

- **现象**：在 Windows + RoboStack 环境里 `colcon build` 会在第一个包上挂住
  （超过 10 分钟无输出、进程不退出）。同样的包用 `python setup.py build` 手动跑是成功的。
- **判断**：这是 Windows + RoboStack 组合下的 colcon 兼容问题，**与包本身无关**；
  Ubuntu 22.04 上 `colcon build` 是标准流程。
- **影响**：验收脚本在检测不到 `ros2 run` 可执行文件时会自动退回
  `python -m <模块>` 方式启动节点，所以功能验证不受影响；但
  **`setup.py` / `package.xml` / `setup.cfg` 的"能被 colcon 正确安装"这一点，
  在 Windows 侧没能验证**。
- **怎么补**：在 Ubuntu 上跑一次
  `bash scripts/build.sh && source install/setup.bash && bash scripts/acceptance.sh all`，
  全绿即可闭环。

### 3.2 rosbag 的 `metadata.yaml` **自动生成**未在 Windows 侧验证

- **现象**：`ros2 bag record` 被 `taskkill /F` 强杀后不会写 `metadata.yaml`；
  用 `CTRL_BREAK_EVENT` 也没能触发优雅收尾。
- **判断**：rosbag2 靠 Ctrl+C 收尾，Windows 上模拟这个信号很麻烦；
  Ubuntu 上 `Ctrl+C` 是标准操作，不会遇到。
- **已经补的措施**：项目自带 `scripts/rebuild_bag_metadata.py`，能从 `.db3` 重建
  `metadata.yaml`。**回放链路已经用它验证通过**：
  `ros2 bag info` 正确报出 1042 条消息 / 14.09 秒 / 两个话题，
  `ros2 bag play --rate 5` 正常打开数据库并播放。
- **仍未验证**：Ubuntu 上按 Ctrl+C 后 `metadata.yaml` 是否**自动**生成
  （这是 rosbag2 的标准行为，风险很低）。

### 3.3 键盘遥控的交互行为

- **未验证**：`keyboard_teleop` 在真实终端里的按键响应（依赖 termios 和 TTY）。
- **已验证**：按键 → 速度的映射逻辑（单元测试 8 项）；
  在非 TTY / 非 Linux 环境下会以退出码 2 给出明确提示，而不是抛异常。
- **怎么补**：在 Ubuntu 终端里跑 `ros2 run m1_turtle_basics keyboard_teleop`，
  按 w/a/s/d 看乌龟是否响应、松手是否自动停。

### 3.4 `ros2 launch` 的端到端启动

- **未验证**：`ros2 launch m1_bringup m1_demo.launch.py` 真正把三个节点拉起来。
- **已验证**：launch 文件能在真实 ROS 2 里被解析成合法的 LaunchDescription，
  参数与节点动作都符合预期（见 2.5）。之所以不能端到端，是因为 launch 通过
  ament index 找包，而 ament index 由 `colcon build` 生成（见 3.1）。
- **怎么补**：Ubuntu 上编译后跑一次 `ros2 launch m1_bringup m1_demo.launch.py`。

> `teleport_demo`（service 瞬移）原本也在未验证清单里，
> 2026-10-18 已补验通过，见 2.3。

## 4. 复现步骤

### 4.1 在 Ubuntu 22.04 上（目标环境，推荐）

```bash
cd "/media/<你的用户名>/Data/Vibe Coding/patrol-robot-ros2"
bash scripts/setup_ubuntu_ros2.sh
source /opt/ros/humble/setup.bash
bash scripts/check_env.sh
bash scripts/build.sh && source install/setup.bash
bash scripts/acceptance.sh all
```

### 4.2 在 Windows 上（复现本文档的验证）

环境已装好，直接跑：

```powershell
$env:MAMBA_ROOT_PREFIX = 'C:\ros2'
$mm = 'C:\_ros2_verify\micromamba.exe'
& $mm run -p 'C:\ros2\envs\humble' python 'D:\Vibe Coding\patrol-robot-ros2\scripts\acceptance.py' all
```

如果不需要了，删掉 `C:\ros2`（约 2 GB）和 `C:\_ros2_verify` 即可，
不影响项目本身。
