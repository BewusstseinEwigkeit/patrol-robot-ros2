## A. 已经踩到的坑

### A1. bash 脚本报 `$'\r': command not found`

- **现象**：在 Ubuntu 上跑 `bash scripts/build.sh`，报
  `bash: build.sh: /bin/bash^M: bad interpreter` 或 `$'\r': command not found`。
- **原因**：脚本在 Windows 下编辑/生成时被存成了 CRLF 换行，Linux 的 bash 把
  `\r` 当成命令的一部分。
- **解法**（三选一）：

  ```bash
  # 1) 一次性转换整个项目
  cd "/media/<你的用户名>/Data/Vibe Coding/patrol-robot-ros2"
  find . -name "*.sh" -exec sed -i 's/\r$//' {} +

  # 2) 只转一个文件
  sed -i 's/\r$//' scripts/acceptance.sh

  # 3) 让 git 永远不引入 CRLF
  git config --global core.autocrlf input
  ```

  预防：在 Windows 侧的编辑器里把 `.sh` 的行尾设成 LF；本工作区的脚本已经
  统一转成 LF。

### A2. 在 Windows 上写的 `launch` 文件里，参数变成了字符串

- **现象**：`launch` 文件里写了 `--x`, `str(LaunchConfiguration("camera_x"))`，
  启动后坐标是 `LaunchConfiguration('camera_x')` 这一串字面量，或者直接报错。
- **原因**：`LaunchConfiguration` 是一个"占位符对象"，只有在 launch 运行时才会
  被替换成真实值。对它调 `str()` 得到的是它的 `repr`，不是值。
- **解法**：是数值就转字符串，是 `LaunchConfiguration` 就原样传给 launch：

  ```python
  from launch.substitutions import Substitution

  def _num(value):
      return value if isinstance(value, Substitution) else str(value)
  ```

  本工作区的 `src/m1_tf2_demo/launch/m1_tf2.launch.py` 里就是这么处理的。

### A3. `rclpy.shutdown()` 在定时器回调里调用后抛异常

- **现象**：节点跑到 `run_seconds` 自动停时，终端刷出一串
  `ExternalShutdownException` 或 `RCLError: rcl_shutdown already called`。
- **原因**：在回调里请求关闭上下文，`rclpy.spin()` 会以异常方式退出。
- **解法**：捕获它就行，这不是错误：

  ```python
  from rclpy.executors import ExternalShutdownException
  try:
      rclpy.spin(node)
  except (KeyboardInterrupt, ExternalShutdownException):
      pass
  ```

### A4. 角度积分出现莫名其妙的 2π 跳变

- **现象**：累计转角比理论值大很多；乌龟明明只转了一圈，统计出来是两圈。
- **原因**：`theta` 在 `+π` 和 `-π` 之间回绕，直接做差会得到约 `2π` 的假跳变。
- **解法**：做差之前先归一化到 `(-π, π]`：

  ```python
  def normalize_angle(a):
      while a > math.pi:  a -= 2 * math.pi
      while a <= -math.pi: a += 2 * math.pi
      return a
  ```

  见 `src/m1_pubsub_demo/m1_pubsub_demo/trajectory_stats.py`，并有单元测试
  `tests/test_trajectory_stats.py::test_角度回绕不会算爆` 钉住它。

### A5. `ros2 bag record` 报"话题不存在"

- **现象**：`ros2 bag record` 一启动就提示某个话题不存在，录出来的包是空的。
- **原因**：录制进程启动得比发布者早，那一刻话题还没被创建。
- **解法**：延迟启动录制（本工作区用 `TimerAction(period=2.0, ...)`），
  或者录 `-a`（全部话题）并接受前两秒的空档。

### A6. 双系统下，Windows 改过的文件在 Ubuntu 里看不到

- **现象**：Windows 里明明改了脚本，切到 Ubuntu 还是旧内容。
- **原因**：Windows 开了"快速启动"，关机其实是休眠，NTFS 分区没有干净卸载。
- **解法**：Windows 里执行"完全关机"（`shutdown /s /t 0`，或按住 Shift 点关机），
  或者关掉控制面板里的"启用快速启动"。

### A7. 切系统后时间差 8 小时，rosbag 时间戳全乱

- **现象**：Ubuntu 里 `date` 比实际时间早/晚 8 小时；`ros2 bag info` 的起止时间
  看起来是昨天；tf2 查询报 "Lookup would require extrapolation into the future"。
- **原因**：Windows 把硬件时钟当本地时间，Ubuntu 当 UTC。
- **解法**：Ubuntu 侧让硬件时钟用本地时间（二选一，别两边都改）：

  ```bash
  timedatectl set-local-rtc 1 --adjust-clock
  ```

  tf2 的"未来时间"报错基本都跟时钟有关，先看时钟再看代码。

### A8. 在 Windows（RoboStack）上 `colcon build` 会挂住

- **现象**：在 Windows 的 RoboStack 环境里跑 `colcon build`，第一个包构建时
  长时间无输出，进程不退出；而同样的包用 `python setup.py build` 手动跑是成功的。
- **原因**：这是 **Windows + RoboStack 组合下的 colcon 兼容问题**，与包本身无关。
  真实目标环境 Ubuntu 22.04 上不存在该问题。
- **解法**：Ubuntu 上正常 `colcon build` 即可。本工作区的 Windows 侧验证改用
  `PYTHONPATH` 直接运行模块（见 `docs/04_验证边界说明.md`）。

### A9. `setup.py` 里写 `tests_require` 会有警告

- **现象**：构建时打印 `UserWarning: Unknown distribution option: 'tests_require'`。
- **原因**：新版 setuptools 已废弃该字段。
- **解法**：删掉它，测试依赖写进 `package.xml` 的 `<test_depend>`。

### A10. 忘了 source `install/setup.bash`

- **现象**：`ros2 run m1_pubsub_demo circle_driver` 报
  `Package 'm1_pubsub_demo' not found`。
- **原因**：`colcon build` 只把包装到 `install/`，需要 source 才会进 `AMENT_PREFIX_PATH`。
- **解法**：

  ```bash
  source install/setup.bash
  ```

  每次新开终端都要做一次（可以加进 `~/.bashrc`，但要注意工作区路径变化）。

### A11. rosbag 录完了，`ros2 bag info` 却说找不到 metadata

- **现象**：`ros2 bag info ~/m1_bags/m1_demo_xxx` 报
  `Could not find metadata in bag directory`，但目录里明明有 `.db3` 文件。
- **原因**：rosbag2 靠 **Ctrl+C** 触发收尾时才写 `metadata.yaml`。
  用 `kill -9`、任务管理器强杀、或者机器断电，数据写进 `.db3` 了，
  但索引文件没生成。数据没丢，只是缺一份"说明书"。
- **解法**：用本工作区自带的工具把说明书补出来：

  ```bash
  python3 scripts/rebuild_bag_metadata.py ~/m1_bags/m1_demo_xxx
  ros2 bag info ~/m1_bags/m1_demo_xxx      # 现在能正常读
  ros2 bag play --rate 5 ~/m1_bags/m1_demo_xxx
  ```

  已验证：一个被强杀的包重建后，`ros2 bag info` 正确报出 1042 条消息 /
  14.09 秒 / 两个话题，回放也正常。
- **预防**：停录制一律用 Ctrl+C，不要用 `kill -9`。
