# 06 · 给两位队友 + 月末例会怎么讲

> M1 是「全员共同月」，所以这个工作区不是只给定位线的。
> 这份文档解决两件事：**队友怎么上手**、**月末例会上怎么讲**。

---

## 第一部分：给队友

### 一句话说明

`patrol-robot-ros2` 是 M1 的公共工作区：四周的实操代码、环境脚本、
一键验收脚本都在里面。三个人都用同一套，谁的进度落后可以直接对照检查点表。

### 三条线各自的重点

| 线 | M1 阶段要额外留意的东西 |
|---|---|
| **定位线**（本人） | `src/m1_tf2_demo/` —— 坐标树是整个项目的地基，M4–M6 的 VIO、EKF 全都挂在 `world → odom → base_link` 这条链上。**重点理解 `lookup_transform` 的方向** |
| **视觉对位线**（计算机同学） | `src/m1_pubsub_demo/` —— M4 之后你要把"桩在画面里的位置 + 距离"发成话题，现在这个包就是最好的模板：一个节点发、一个节点收，参数用 `--ros-args -p` 传 |
| **平台集成线**（机器人同学） | `src/m1_bringup/launch/` —— M5 的状态机要用 launch 拉起一堆节点，现在这条 launch 就是最小可用版本。**另外：模组供应商的协议文档要在 M1 内催到** |

### 上手步骤（约 30 分钟）

```bash
# 1. 切到 Ubuntu，进工作区
cd "/media/<你的用户名>/Data/Vibe Coding/patrol-robot-ros2"

# 2. 装环境（已装会跳过）
bash scripts/setup_ubuntu_ros2.sh

# 3. 编译 + 验收
bash scripts/build.sh && source install/setup.bash
bash scripts/acceptance.sh all
```

全绿之后，挑自己那条线的包，把代码读一遍，重点是注释里"为什么这么写"。

### 不要做的事

- **不要**在这个工作区里塞 M2 之后的东西（标定、VINS、YOLO）。
  M1 的目标是"把 ROS 2 的手感练出来"，掺进来会让 M1 永远结不掉。
- **不要**改 `docs/02_逐周任务与验收.md` 里的检查点定义。
  那是三个人的共同标准，要改先在例会上说。
- **不要**把私密信息（token、账号、身份证号）写进这个目录。

## 第二部分：月末例会怎么讲

M1 的检查点是一句话：「不看教程能独立做出 launch 拉起 画圆 + 打印位姿 + 录包 三个节点」。

汇报建议按这个顺序讲（约 8 分钟）：

### 1. 先给结果（1 分钟）

```bash
bash scripts/acceptance.sh all
```

直接投屏这一屏，`通过：18  未过：0`。

### 2. 再讲这三个数字（2 分钟）

| 数字 | 说明什么 |
|---|---|
| 轨迹外接框 **3.0×3.0**，宽高比 **1.0** | 设的半径是 1.5 m，画出来的圆直径正好 3.0 m —— 速度指令到实际运动这条链路是对的 |
| 相机安装偏移 **(0.150, 0.000, 0.100)** | 和 launch 里写的一样，误差小于 1 毫米 —— tf2 坐标树换算是对的 |
| rosbag 里 **2219 条 Pose 消息** | 录包不是"看起来在录"，是真的落盘了 |

> 讲数字比讲"我学会了 turtlesim"有说服力得多。评审和老师都吃这一套。

### 3. 讲踩过的坑（3 分钟）

从 `docs/03_踩坑日志.md` 里挑两三个，按"现象 → 原因 → 解法"讲。
最推荐这两个：

- **A4 角度回绕**：为什么累计转角会莫名其妙多出 2π。这个坑在 M6 的 EKF 里会再遇到一次。
- **A5 rosbag 录不到话题**：录制进程比发布者先启动。M5 的状态机联调时同理。

踩坑日志是计划表里点名要的，也是简历素材。

### 4. 最后讲遗留和下一步（2 分钟）

诚实地讲还没验证的部分（见 `docs/04_验证边界说明.md` 第 3 节）：
colcon 构建、launch 端到端、交互式键盘——这三件要在 Ubuntu 上补。

然后说 M2 自己的打算：打印标定板 → Kalibr 双目内参 → 第一份标定 yaml。

## 第三部分：M2 末要用的"接口冻结"模板

计划表里写：「M2 末三人开会，用文档定死互相传数据的 topic 名、消息格式、坐标系」。

开会时直接填这张表，填完存档：

```text
接口冻结记录  v1    日期：____

【坐标系】
  全局参考系：world
  车体坐标系：base_link（原点在车体中心，x 朝前，y 朝左，z 朝上）
  坐标树约定：world → odom → base_link → {imu_link, camera_link}
  发布者：odom→base_link 由定位线发布；base_link→传感器 由平台线发布（静态）

【话题】
  定位结果     话题：__________  类型：nav_msgs/Odometry    发布者：定位线
  桩相对位置   话题：__________  类型：geometry_msgs/PoseStamped  发布者：视觉线
  速度指令     话题：/cmd_vel    类型：geometry_msgs/Twist    发布者：状态机
  电池电量     话题：__________  类型：sensor_msgs/BatteryState  发布者：平台线
  充电功率     话题：__________  类型：__________            发布者：平台线

【消息字段约定】
  （例如：桩相对位置一律用 camera_link 还是 base_link？写清楚）

【谁负责验证】
  每条话题的发布者负责提供一个"能单独跑起来的最小 demo"。
```

> 这张表现在就可以先抄一份存着。M1 剩下的时间里，每当有人想改话题名，
> 就说明为什么要等 M2 末再定——**接口一冻结就不许私下改**。
