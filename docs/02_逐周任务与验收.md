## W2 · 建包、发布、订阅

### 要会什么

- 一个 ROS 2 Python 包最少需要哪几个文件？（`package.xml` / `setup.py` / `setup.cfg` / `resource/<包名>`）
- `colcon build` 之后为什么要 `source install/setup.bash`？
- 发布者和订阅者是怎么"对上"的？（靠话题名 + 消息类型，不靠先后顺序）

### 动手

```bash
bash scripts/build.sh
source install/setup.bash

# 终端 1
ros2 run turtlesim turtlesim_node

# 终端 2：画圆
ros2 run m1_pubsub_demo circle_driver --ros-args -p radius:=1.5 -p linear_speed:=2.0

# 终端 3：看位姿
ros2 run m1_pubsub_demo pose_monitor --ros-args -p report_period:=1.0
```

自己改一改：

```bash
# 半径 3 米，慢一点
ros2 run m1_pubsub_demo circle_driver --ros-args -p radius:=3.0 -p linear_speed:=1.5

# 让它自己跑 8 秒就停（验收脚本就是这么用的）
ros2 run m1_pubsub_demo circle_driver --ros-args -p run_seconds:=8.0
```

### 关键公式

圆周运动只有一个关系要记：

```
v = w × r        v 线速度 (m/s)，w 角速度 (rad/s)，r 半径 (m)
```

所以 `radius:=1.5`、`linear_speed:=2.0` 时，节点内部会算出
`w = 2.0 / 1.5 = 1.333 rad/s`。

跑 9 秒应该转过 `1.333 × 9 ≈ 12 rad`（约 1.9 圈），走过的路程约 `2.0 × 9 = 18 m`
（实测会略少，因为启动有几秒开销）。

### 检查点

```bash

```

- [ ] W2.1 两个可执行文件注册成功

## W4 · tf2 坐标树

### 要会什么

- 为什么要有一棵坐标树，而不是每个模块各自记坐标？
- `static_transform_publisher` 和普通 broadcaster 的区别是什么？
- `lookup_transform("world", "camera_link", t)` 到底是谁换算到谁？

### 坐标树设计（和真车一致）

```text
world
  └─ odom                  ← 静态；真车上这一跳是 EKF 修正漂移的地方（M6）
       └─ base_link        ← 会动；这里由 turtlesim 位姿驱动
            ├─ imu_link    ← 静态
            └─ camera_link ← 静态
```

> 真车上 `base_link → camera_link` 的平移量就是你拿尺子量出来的相机安装位置。
> launch 文件里默认写的是 `(0.15, 0, 0.10)`，等相机真装上去，把这三个数字换掉就行。

### 动手

```bash
ros2 launch m1_tf2_demo m1_tf2.launch.py

# 另一个终端：直接问树
ros2 run tf2_ros tf2_echo world camera_link
ros2 run tf2_ros tf2_echo world base_link

# 把整棵树画成 PDF
ros2 run tf2_tools view_frames
evince frames.pdf      # 或者 xdg-open frames.pdf
```

让乌龟动起来，再看 `tf2_echo` 的输出，会发现 `camera_link` 的坐标跟着变——
这说明坐标树是"活"的，而不是一堆静态数字。

### 检查点

```bash

```

- [ ] W4.1 `tf2_echo` 能查到 `world → camera_link`
- [ ] W4.2 `tf_listener` 打印出相机在世界坐标系下的位姿
- [ ] W4.3 `tf2_monitor` 确认这条链连通
