## 一、概念题

**Q1.** `topic`、`service`、`action`、`param` 各自适合什么场景？举一个本项目里的例子。

**Q2.** 为什么改乌龟的速度要发一个 `geometry_msgs/Twist` 消息，而不是调用一个"设置速度"的函数？

**Q3.** `ros2 topic pub -r 10` 里的 `-r 10` 是什么意思？去掉它会怎样？

**Q4.** 发布者和订阅者谁先启动有影响吗？为什么？

**Q5.** `colcon build` 之后为什么必须 `source install/setup.bash`？不 source 会报什么错？

## 二、代码题

**Q6.** `circle_driver` 里，设 `radius:=2.0`、`linear_speed:=1.0`，节点算出的角速度是多少？跑 10 秒大约转几圈？

**Q7.** 打开 `src/m1_pubsub_demo/m1_pubsub_demo/trajectory_stats.py`，解释 `normalize_angle` 为什么必须有。如果不做归一化，让乌龟转一整圈，累计转角会算出多少？

**Q8.** `pose_monitor` 的 `run_seconds` 到点后做了什么？为什么不是简单地把定时器停掉就完事？

**Q9.** `keyboard_teleop` 里的 `key_timeout` 参数解决什么问题？如果设成 0 会发生什么？

**Q10.** `teleport_demo` 用的是 service 还是 topic？为什么这个场景用 service 更合适？

## 三、launch 与 tf2

**Q11.** `m1_demo.launch.py` 里，`DeclareLaunchArgument` 声明的参数是怎么一路传到 `circle_driver` 节点里的？说出中间经过的两个对象。

**Q12.** launch 文件里为什么不能写 `str(LaunchConfiguration("radius"))`？

**Q13.** `record:=true` 时，录包进程为什么要用 `TimerAction` 延迟 2 秒启动？

**Q14.** 坐标树 `world → odom → base_link → camera_link` 里：
   a) 哪一跳是静态的、哪一跳会动？
   b) `lookup_transform("world", "camera_link", t)` 是在问"谁在谁里的坐标"？
   c) 如果相机装在车体前方 0.15 m，乌龟转过 90° 后，相机在 `world` 下的偏移量还是 (0.15, 0) 吗？

**Q15.** 为什么一个 child frame 只能有一个父 frame？如果两个节点都发布 `odom → base_link` 会发生什么？

## 答案与解析

<details>
<summary>点开看答案</summary>

**A1.**
- `topic`：**持续、单向、异步**。例：`/turtle1/cmd_vel` 一直发速度；`/turtle1/pose` 一直报位置。
- `service`：**一次性、有应答**。例：`/turtle1/teleport_absolute` 请求"把乌龟放到 (5.5, 5.5)"，服务端回"放好了"。
- `action`：**耗时任务、可反馈、可取消**。例：M5 之后"开到充电桩"这种要走几秒、中途可能要取消的任务。
- `param`：**配置项**，启动时或运行中设置。例：turtlesim 的 `background_r`。

**A2.** 因为 ROS 2 的节点是**松耦合**的：发速度的节点不需要知道谁在收，收速度的节点也不需要知道谁在发。只要话题名和消息类型对上就能通信。如果做成函数调用，两个节点就必须直接持有对方的引用，无法各自独立启动、替换或跨机器运行。

**A3.** `-r 10` 表示**每秒发 10 次**（rate）。去掉之后 `ros2 topic pub` 默认只发一次就退出，乌龟只会动一瞬间。乌龟需要持续的指令流才会持续运动——这也是为什么真车上的速度指令要按固定频率发，并配一个"超时停车"的保护。

**A4.** 没有影响，顺序随意。这正是 topic 的好处：发布者可以在没有订阅者时照常发（消息被丢弃），订阅者也可以先等着。`circle_driver` 先起还是 `turtlesim` 先起都能正常工作。

**A5.** `colcon build` 把包安装到工作区的 `install/` 目录，并把包登记进 `install/share/ament_index`。`source install/setup.bash` 的作用是把 `install/` 加进 `AMENT_PREFIX_PATH` 和 `PYTHONPATH`，ROS 才能找到你的包。不 source 会报 `Package 'm1_pubsub_demo' not found`。

**A6.** `w = v / r = 1.0 / 2.0 = 0.5 rad/s`。10 秒转过 `0.5 × 10 = 5 rad`，约 `5 / (2π) ≈ 0.8 圈`。走过的路程约 `1.0 × 10 = 10 m`（周长是 `2π × 2 = 12.6 m`，所以不到一圈，和上面的 0.8 圈一致）。

**A7.** 因为 `theta` 会在 `+π` 和 `−π` 之间回绕。假设连续两帧的 theta 是 `3.14` 和 `−3.14`，实际只转了约 `0.003 rad`，但直接相减得到 `−6.28`，绝对值就是 `6.28`。转一整圈（720 帧、每帧 0.5°）不做归一化的话，累计转角会是 `2π` 再加上每次跨越 ±π 时多出来的 `2π`——一正一负两处，结果是 **`2π + 4π = 6π` 左右**（约 18.85 rad），而不是正确的 `2π`（6.28）。本项目有单元测试 `test_角度回绕不会算爆` 钉住这一点。

**A8.** 它先 `publish(Twist())` 发一条**零速度**把乌龟停下，再把统计写进 `summary_json`，最后才 `rclpy.shutdown()`。如果只是停掉定时器，乌龟会带着最后一次的速度一直跑下去（turtlesim 不会自己停）。

**A9.** 解决"松手不停车"：如果 `key_timeout` 秒内没有新按键，自动发零速度。设成 0 就关掉这个保护，乌龟会一直保持最后一次的速度跑到撞墙。

**A10.** 用 **service**。因为"把乌龟瞬移到某点"是**一次性、需要确认结果**的操作；用 topic 发速度的话，你还得自己写闭环控制让它走到目标点。M4 之后向充电模组要"当前功率"也是 service 类的请求-应答。

**A11.** `DeclareLaunchArgument("radius", ...)` 声明参数 → `LaunchConfiguration("radius")` 拿到这个参数的**占位符** → 放进 `Node(parameters=[{"radius": radius}])` → launch 在启动节点时把它展开成 `--ros-args -p radius:=...`。中间的两个对象就是 `DeclareLaunchArgument` 和 `LaunchConfiguration`。

**A12.** 因为 `LaunchConfiguration` 是个占位符对象，只有在 launch 运行时才会被替换成真实值。对它调 `str()` 得到的是它的 `repr`（类似 `LaunchConfiguration('radius')`），会被当成字面量传给节点。

**A13.** 因为 `ros2 bag record` 启动时如果话题还不存在，会报警告甚至录不到。等 2 秒让 turtlesim 先把话题建出来。M5 的状态机联调时会遇到同样的问题。

**A14.**
   a) `world → odom` 和 `base_link → camera_link` 是静态的；`odom → base_link` 会动（由 `turtle_tf_broadcaster` 发布）。
   b) 是问"**`camera_link` 在 `world` 坐标系下的坐标是多少**"。记忆法：`lookup_transform(target, source)` = "我要在 target 里看 source"。
   c) **不是**。相机的安装位置是相对 `base_link` 固定的 `(0.15, 0, 0.10)`，但换算到 `world` 时会叠加车体的旋转。转过 90° 后，在 `world` 下的偏移变成 `(0, 0.15, 0.10)` 方向。这也是为什么验收脚本 W4.2 要查 `base_link → camera_link` 而不是用世界坐标做差。

**A15.** 因为 tf2 要维护一棵**树**（每个 frame 只有一个父），才能唯一确定任意两个 frame 之间的关系。如果两个节点都发布 `odom → base_link`，接收端会看到两个互相矛盾的变换，表现为数值来回跳变、`tf2_echo` 输出抖动、甚至报 "TF_OLD_DATA"。所以本工作区里 `odom → base_link` 只由 `turtle_tf_broadcaster` 一个节点发布。

</details>
